# Idea discovery — methodology

## 1. Advantage inventory

For each of the user's assets, record:

| Asset | Proof (project, role, audience size) | Who else has it | How it is monetisable |
| ----- | ------------------------------------ | --------------- | --------------------- |

Assets with no proof line are interests, not advantages. Say so and do not build
a recommendation on them.

## 2. Pain mining questions

Ask about the last 12 months of their working life:

- Which task did you do manually every week and resent?
- Which reports or spreadsheets did a colleague rebuild from scratch?
- What did your team pay an external vendor for that looked simple?
- Where did a process break when the team grew?
- What complaint did you hear from a customer more than twice?

A candidate idea needs a specific memory behind it, not a category.

## 3. Scoring rubric

Score each candidate 1–5 on five criteria, then weight:

| Criterion                    | Weight | 1 means                      | 5 means                             |
| ---------------------------- | ------ | ---------------------------- | ----------------------------------- |
| Pain intensity               | 25%    | mild annoyance               | recurring, budgeted, blocking work  |
| Willingness to pay           | 20%    | consumer, free alternatives  | team budget already spent elsewhere |
| Fit with proven skills       | 20%    | would need to learn the core | can ship the core alone this month  |
| Access to buyers             | 20%    | strangers, paid ads only     | can name ten buyers today           |
| Build feasibility in 2 weeks | 15%    | multi-team platform          | one workflow, one user type         |

Weighted total = Σ (score × weight). Report the total and the two weakest
criteria. A candidate below 3.0 on access to buyers is not a first product,
however good the idea is.

## 4. Validation ladder

Run the cheapest rung that can change the decision:

1. **Five problem interviews.** Ask about the last time the problem occurred, what
   they did, what it cost. Do not pitch. Advance if three describe the same
   workflow unprompted.
2. **Landing page with a real price.** One page, one outcome, a button that
   records intent. Advance on 5%+ click-through from 100 targeted visitors.
3. **Concierge delivery.** Do the job manually for one customer for money or a
   written commitment to pay. This is the strongest signal available.
4. **Paid pilot.** Invoice for a small scope. Advance only on an actual invoice.

## 5. Interview script (do not pitch)

- "Walk me through the last time you handled <workflow>."
- "How often does that happen?"
- "What did you do instead when it went wrong?"
- "Who else gets involved, and what do they cost?"
- "What have you tried or bought to fix it?"
- "If this stayed broken for a year, what happens?"

## 6. Kill criteria examples

Write these before the test:

- Fewer than 3 of 5 interviewees describe the same workflow → stop.
- Fewer than 5 of 100 targeted visitors click the priced button → stop.
- No customer agrees to a paid pilot within 3 weeks → stop.

## 7. Red flags in candidate ideas

- The buyer is "developers" with no narrower segment.
- The value depends on data the user cannot legally obtain.
- The idea requires two-sided liquidity to be useful at all.
- The user's only advantage is enthusiasm for the technology.
- Success requires a feature the user cannot build unaided in two weeks.
